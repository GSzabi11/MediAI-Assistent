MediAI API-térkép

A backend összes REST-végpontja szakterületenként. A behúzott sorok beágyazott erőforrások (pl. a megszólalás mindig egy felvétel alatt él). Minden /api hívást a hozzáférési napló automatikusan rögzít.

Beteg és ellátás

A beteg a gyökér: minden klinikai adat hozzá kötődik.

/api/patients beteg
  • POST/api/patientsBeteg felvétele (TAJ opcionális)
  • GET/api/patients/{id}Egy beteg
  • GET/api/patientsÖsszes beteg
  • POST/api/patients/searchKeresés TAJ-ra vagy név + anyja neve + születési dátum törzsben keres
/api/medical-cares ellátás
  • POST/api/medical-caresEllátás megnyitása (SBO / AMBULANCE / ECHO)
  • GET/api/medical-cares/{id}Egy ellátás
  • GET/api/medical-cares?patientId=Beteg ellátásai
  • POST/api/medical-cares/{id}/closeLezárás, DB-idővel egyszer
/api/lab-results laboreredmény
  • POST/api/lab-resultsTeljes panel egy tranzakcióban; cenzorált érték elutasítva
  • GET/api/lab-results/{id}Egy eredmény
  • GET/api/lab-results?patientId=&name=Beteg eredményei; name-mel egy vizsgálat trendje
/api/medications gyógyszer
  • POST/api/medicationsRögzítés; forrás csak jóváhagyott állítás lehet
  • GET/api/medications/{id}Egy gyógyszer
  • GET/api/medications?patientId=&activeOnly=Beteg gyógyszerei, szűrhetően a szedettekre
  • POST/api/medications/{id}/discontinueLeállítás; újrakezdés = új sor egyszer
/api/allergies allergia
  • POST/api/allergiesRögzítés; egy anyag betegenként egyszer
  • GET/api/allergies/{id}Egy allergia
  • GET/api/allergies?patientId=Beteg allergiái, ABC-sorrendben

Állítások

Minden orvosnak mutatott állítás: MI · MERRE · MIKOR · HOGY. Jóváhagyás nélkül PENDING.

/api/statements állítás
  • POST/api/statementsRETRIEVED_FACT vagy MODEL_INFERENCE; szabály-állítás csak belső motorból
  • GET/api/statements/{id}Egy állítás, aktuális jóváhagyási állapottal
  • GET/api/statements?patientId=Beteg állításai, klinikai idő szerint
/api/statements/{statementId}/approvals jóváhagyás
  • POST…/approvalsACCEPTED / REJECTED / MODIFIED — csak DOCTOR
  • GET…/approvalsDöntési előzmény, legújabb elöl

Hang

A Python hangmodul kész eredményét fogadja; a hangfolyam nem megy át a Springen.

/api/recordings felvétel
  • POST/api/recordingsFelvétel indítása; az orvos aktív hangprofilja automatikusan
  • GET/api/recordings/{id}Egy felvétel
  • GET/api/recordings?patientId=Beteg felvételei
  • PATCH/api/recordings/{id}/statusRECORDING → PROCESSING → DONE | FAILED
/api/recordings/{recordingId}/utterances megszólalás
  • POST…/utterancesÖsszes megszólalás egyben, csak PROCESSING-ben egyszer
  • GET…/utterancesMegszólalások turnId szerint

Dokumentumok

A fájl lemezen, a hash és a típus a szerver által számolva; a szöveg a RAG és a forrás-hivatkozás alapja.

/api/documents dokumentum
  • POST/api/documentsFeltöltés (multipart: file, patientId, type, clinicalDate)
  • GET/api/documents/{id}Metaadatok
  • GET/api/documents?patientId=Beteg dokumentumai
  • GET/api/documents/{id}/fileA fájl letöltése EXPORT
  • PUT/api/documents/{id}/textKinyert szöveg beállítása egyszer
  • GET/api/documents/{id}/textKinyert szöveg (text/plain)
/api/documents/{documentId}/chunks RAG-darab
  • POST…/chunksPozíciók + 1024 dim. embedding; a szöveget a Spring vágja ki egyszer
  • GET…/chunksDarabok pozíció szerint

Felhasználók és hangprofil

Orvos és admin fiókok. Bejelentkezés még nincs.

/api/users felhasználó
  • POST/api/usersFelvétel; jelszó BCrypt-hash-ként
  • GET/api/users/{id}Egy felhasználó
  • GET/api/users?role=Összes, vagy szerepkör szerint (DOCTOR / ADMIN)
  • POST/api/users/searchFelhasználónévre vagy emailre törzsben keres
/api/voice-profiles hangprofil
  • POST/api/voice-profilesÚj profil; a korábbi aktív automatikusan inaktív lesz
  • GET/api/voice-profiles/{userId}/activeAz orvos aktív profilja
  • GET/api/voice-profiles/{userId}/historyÖsszes profil, régiekkel együtt

Audit

Csak hozzáfűzhető napló; bejegyzést kizárólag az interceptor ír.

/api/access-logs hozzáférési napló
  • GET/api/access-logs?patientId= | ?userId=Ki nézte a beteget, illetve mit nézett a felhasználó
Minden hívásra érvényes: az X-User-Id fejléc adja meg, ki a hívó (ideiglenes, a bejelentkezés bevezetéséig). Nélküle a naplóban üres a felhasználó.
Hibaválaszok: 404 nem létező erőforrás, 409 szabály- vagy állapotütközés, 400 hibás bemenet — a saját kivételek ProblemDetail formában, üzenettel.
